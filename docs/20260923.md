Target: `route` plugin, `main` (0.9.4, unreleased).

## Why

- Per-token price is not per-task cost. The number that decides a tier is
  **cost per accepted task**: a builder miss also costs a reviewer run, a main-session
  adjudication, and a resume. The plugin cannot report that number today.
- **Cache reads dominate cost, not output.** One measured Sonnet 5 builder run
  (91 turns): cache reads 4.54M tokens = 67% of cost, cache writes 25%, output 10.5k
  tokens = 8%. Effort changes cost mainly through the number of turns, because each
  turn replays the whole context.
- **Opus 5.5 cache reads cost the same per token as Sonnet 5** ($0.20/MTok each). Opus
  pays 2x only on cache writes and output. At equal token counts that builder run costs
  $1.80 on Opus 5.5 against $1.35 on Sonnet 5 (+33%); two reviewer runs cost +73% and
  +79% (+$0.22 to +$0.30 per review). Opus breaks even on builder if it uses at most
  about 75% of Sonnet's token volume.

## Facts this spec relies on (verified)

- Effort is set **only** in agent frontmatter; the Agent tool has no `effort` parameter.
  Effort is plugin-wide, while `models.<role>` is per project.
- Frontmatter now: `builder` and `reviewer` are `model: opus, effort: medium`. Before
  this revision, builder was `sonnet / xhigh` and reviewer was `sonnet / high`.
- The `model` parameter takes aliases only. On Claude Code 2.1.280 the `opus` family
  maps to `claude-opus-5-5`; on 2.1.278 this project's main-session transcripts show
  `claude-opus-5`. The model id in a subagent transcript (`message.model`) is the record.
- Opus 5.5 list price: $4 in / $20 out, 5m cache write $5, cache read $0.20 (0.05x).
  Its default effort is `medium`, and thinking cannot be disabled.
- Sonnet 5 list price: $2 / $10 (the introductory price became the standard price).
- A resume (`SendMessage`) cannot change model. Any model change is a fresh dispatch.
- `/route:init` writes all four `models.<role>` keys, so existing projects pin
  `builder: "sonnet"` and `reviewer: "sonnet"`, and now run Sonnet at `medium`.
- The dispatch log holds many rows that are not route roles: in this repo, 27 of 34
  SubagentStop rows are `agent_type: unknown` with no `agent_transcript_path`.
- A resume appends to the same agent transcript (SKILL.md Step 5: 11 dispatches produced
  6 transcripts). No agent id in the current log has more than one SubagentStop row, so
  a SubagentStop count is not a resume count.

## Phase 0 — make cost per task measurable

### T1 — pricing table matches list prices — DONE

- `pricing.json`: `claude-opus-5-5` at `4 / 20` with `cacheRead: 0.05`,
  `claude-sonnet-5` at `2 / 10`. Each entry may carry `cacheRead`, which replaces
  `cacheMultipliers.read` for that model.
- `routing_audit.py`: `price_entry()` returns the matched key; `cost()` and
  `dispatch_delta.py` use the per-model cache-read multiplier. The cost-by-model table
  prints `(priced as <key>)`.
- Tests: `tests/test_audit.py`.

### T2 — task identity without a new hook (reduced)

- **Contract**: the audit reads task identity from the agent transcripts that already
  exist. It does not add a PostToolUse(SendMessage) hook and does not log `resolvedModel`
  (the transcript's `message.model` already records the model).
  - `task`: parse the leading `Task: <id>` line of the first user message in the agent
    transcript (the brief). If there is none, use `(untagged)`.
  - `resumes`: count the `type: "user"` entries whose `origin.kind` is `"coordinator"`.
    Confirmed 2026-09-23 on a real resumed builder (`agent-a1b4b6fd78fd9e456.jsonl`): a
    `SendMessage` resume appends to the same `agent-*.jsonl` as an `isMeta` user entry with
    `origin: {"kind": "coordinator"}` and a new `promptId`. Do **not** count non-tool-result
    user messages (the harness injects `isMeta` entries such as the SubagentHandback
    reminder and `[Your previous response had no visible output...]`: that rule gives 3 on
    this transcript instead of 1). Do **not** count distinct `promptId` values (the
    no-visible-output nudge starts a new one: 4 of 9 transcripts would show a false resume).
  - Consider only route roles that have an agent transcript. Drop `unknown` rows that
    have no transcript path.
- **Files**: `route/scripts/routing_audit.py`, `tests/test_audit.py`.
- **Verify**: `python -m pytest -q`; a fixture transcript with a `Task:` line and one
  appended resume message yields that task with `resumes == 1`.
- **Non-goals**: new hooks; logging prompt text into `dispatch.jsonl`.

### T3 — `routing_audit.py --by-task`

- **Contract**: group subagent cost by `task`. Per task, show: builder dispatches, builder
  resumes, reviewer dispatches, models seen, **turns**, **cache_read tokens**, output
  tokens, total cost, and cost split by role. Rows with no task go under `(untagged)`.
  Main-session cost appears once per session and is not split across tasks. Add
  `--by-task` to the `/route:audit` docs.
- **Files**: `route/scripts/routing_audit.py`, `route/commands/audit.md`, `tests/`.
- **Verify**: `python -m pytest -q`; a fixture with two tasks, one of them resumed, shows
  one resume on the right task.
- **Non-goals**: splitting main-thread tokens across tasks; parsing reviewer verdict text.

### T4 — every dispatch carries its task id

- **Contract**: `SKILL.md` Steps 3 and 4 require the brief's first line to be
  `Task: <id>` (use `?-<short slug>` when there is no tracked id), and the Agent
  `description` to begin with the same id. The reviewer dispatch for a builder uses the
  same id.
- **Files**: `route/skills/route/SKILL.md`.
- **Verify**: a dry read of Steps 3–4 shows the rule once in each step; no other step
  changes.

### T5 — baseline from history

- **Contract**: the tier change shipped before a live baseline existed. Use the Sonnet
  builder and reviewer transcripts recorded before 2026-09-23 as the Sonnet baseline. Run
  `--by-task` over them once T2–T3 exist. Untagged history is allowed here; record per
  task: accepted or not, FAIL count, turns, cost.
- **Files**: `docs/field-reports/<date>-tier-baseline.md`.
- **Non-goals**: changing any tier.

## Phase 2 — effort experiment on Opus (revised T7)

### T7 — paired effort arms

- **Contract**: arm A = `opus / medium` (current). Arm B = `opus / low`. Optional arm
  C = `sonnet / xhigh` as the Sonnet reference; this arm needs the frontmatter effort
  temporarily set to `xhigh` and `models.builder` set to `sonnet`.
  **Paired design**: every arm runs the same task set (at least 8 tasks, at least 3
  multi-file) with the same brief, each from a `git worktree` at the same base commit.
  Compare cost per accepted task, FAIL count, and turns.
  Keep `low` only if cost per accepted task drops **and** FAILs rise by no more than one
  per ten tasks. Rough break-even from one sample: `low` must add fewer than one FAIL
  per 3–4 tasks, because `low` saves roughly $0.4–0.5 per task at most, and one FAIL
  cycle costs a reviewer run, a builder resume, and an adjudication.
- **Files**: `route/agents/builder.md` (only if a new value wins), `README.md`,
  `docs/CHANGELOG.md`, `docs/field-reports/<date>-builder-effort.md`.
- **Verify**: SubagentStop rows for builder show the chosen effort.
- **Non-goals**: a per-lane effort (effort is one value per agent type).

### T8 — escalate a Sonnet builder to Opus — PARKED

Builder already defaults to Opus. Revisit only if T7 arm C wins and builder returns to
Sonnet. The classification rule stays as it was written: a spec defect goes back to the
spec at the same tier; a clear implementation miss triggers a fresh `model: opus`
dispatch. A resume never switches model.

## Risks to watch

- **Effort coupling.** Projects that pin `sonnet` for builder or reviewer now run Sonnet
  at `medium`. `/route:doctor` warns about this.
- **Alias drift.** `opus` follows the installed Claude Code. A version rollback, or
  `ANTHROPIC_DEFAULT_OPUS_MODEL=claude-opus-5`, silently moves subagents to Opus 5.
  Compare runs only within one resolved model id.
- **Same model as the main session.** With builder on Opus 5.5, routing keeps the main
  context small but no longer downgrades the model. Judge it by cost per accepted task,
  not by the model split in `/route:audit`.
- **Spec defects look like weak builders.** A stronger builder does not fix a wrong
  spec. Keep the Step 5 "FAIL, 2nd time → fix the spec" rule.
- **Small samples.** 8 paired tasks show direction, not significance.
- **Delegation suppression on Opus main sessions** (reported as anthropics/claude-code#80988,
  not verified here). If `/route:audit` shows zero subagent transcripts, check this first.
