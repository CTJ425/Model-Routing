Model-Routing (`route`) 系統架構與機制指南

本指南深入解析 route 插件的模型分流架構、多代理人協同流程、Pre/PostToolUse Hook 守衛機制、審查閉環與記帳稽核系統。

01. 核心理念與架構總覽

在大語言模型 (LLM) 的代理工作流中，成本的大頭並非單次輸出的生成量，而是 Context Replay（上下文重播懲罰）：

⚠️ Context Replay 核心痛點
主會話 (Main Thread) 只要讀取了一次大檔案或傾印了幾千行的測試日誌，這些內容就會在該 Session 後續的每一個回合 (Turn) 不斷被灌入 Context 並被重複計費。因此，讓頂級昂貴模型直接讀取整份代碼庫或撰寫大量模板代碼是極大的浪費。

route 插件的解決方案：
將昂貴的主會話模型 (Boss) 當作「架構師與裁判」，只負責規劃、寫規格契約與裁決；將大範圍閱讀、實作寫入、靜態審查與文檔記帳等機械工作，全權委派給 4 個平價的專屬 Subagent。

02. 五大角色分工矩陣

👑 Boss Session Tier
職責：任務分級、撰寫 Inline Brief 與 Spec、編寫失敗測試、裁決審查回饋。
⛔ 嚴禁：直接撰寫生產程式碼、直接編輯追蹤文檔（除非 Lane 0 極小改動）。
🛠️ 具備工具：全工具（受 Hook 政策規範）
🔍 scout Haiku
職責：代碼地圖繪製 (Map mode)、日誌與堆疊壓縮 (Compress mode)。
⛔ 嚴禁：撰寫任何檔案、執行任何 Bash 指令、輸出超過 40 行。
🛠️ 具備工具：Read, Glob, Grep
🔨 builder Sonnet
職責：嚴格依據 Files 清單實作代碼、逐字執行 Verify 命令驗證。
⛔ 嚴禁：修改測試檔案、修改 Spec/文檔、添加未要求的架構或錯誤處理。
🛠️ 具備工具：Read, Glob, Grep, Write, Edit, Bash
🕵️ reviewer Sonnet
職責：比對 Builder Diff 與 Spec，檢查 7 大風險觸發器，回傳 PASS/FAIL/RISK。
⛔ 嚴禁：修復任何代碼、提出修復建議方案、執行 Bash。
🛠️ 具備工具：Read, Glob, Grep
✍️ scribe Haiku
職責：機械化謄寫進度與成果至 docs/agent/ 追蹤文檔、安全原子滾動歸檔。
⛔ 嚴禁：撰寫生產代碼、推測數值、偽造未來時間戳。
🛠️ 具備工具：Read, Glob, Grep, Write, Edit, Bash (限 cat >>)

05. 7 階段生命週期詳解 (Step 0 ~ Step 6)

0
Step 0: Lane 分級與冷啟動門檻評估 👑 Boss

評估任務所需的推理深度、錯誤代價與主觀判斷：

  • Lane 0 (Inline Surgical)：極小手術式修改（如錯字、版本號更新、單行修復）。由 Boss 在主會話就地修改並驗證，免除 Subagent 冷啟動門檻費用。
  • Lane 1 (Bounded Feature/Fix - 預設)：已知模組內的邊界明確任務。Boss 在 Prompt 撰寫 5 段式 Inline Brief。
  • Lane 2 (Elevated Risk)：未知原因 Bug、狀態/DB/認證變更、跨模組變更。Boss 建立正式 Spec 文檔並預先編寫 Failing Tests。
1
Step 1: 代碼拓撲繪製 (Codebase Mapping) 🔍 scout (Haiku)

僅在目標代碼區域未被探索時分派。Scout 進行唯讀掃描，回傳限制在 40 行以內 的結構化摘要 (ENTRY, DEFINES, CALLERS, STATE, TESTS, GAPS)，大幅節省主會話 Token。

2
Step 2: 規格契約制定 (Spec / Brief Authoring) 👑 Boss

由高階模型擬定嚴格的任務邊界契約：

Task: <任務 ID 與簡述>
Contract: <輸入、輸出、錯誤處理、不變性承諾>
Files: src/...   <- 窮舉允許修改的檔案清單，其餘一律不准動
Verify: <精確的驗證指令>
Non-goals: <明確禁止的額外行為>
3
Step 3: 程式碼實作 (Implementation & Build) 🔨 builder (Sonnet)

Builder 僅能修改 Files 清單中的檔案，禁止修改任何測試檔案、Spec 或追蹤文檔。實作完成後逐字執行 Verify 驗證指令並回報結構化報告。

4
Step 4: 靜態審查與風險檢查 (Review & Risk Triggers) 🕵️ reviewer (Sonnet)

依據 review.policy 政策執行。Boss 將 git diff 寫入專案外的暫存檔傳遞給 Reviewer（比全檔閱讀節省約 6.8x Token）。Reviewer 依據 7 大風險觸發器進行判定，只報問題不提解法。

5
Step 5: 裁決與修復閉環 (Adjudication Loops) 👑 Boss
  • PASS：進入 Step 6。
  • FAIL (第 1 次)：Boss 撰寫精確修復指令，透過 SendMessage 恢復 (Resume) 既有 Builder 續做。
  • FAIL (第 2 次)：約 80% 機率為規格瑕疵，Boss 修正 Spec 後重新開局。
  • FAIL (第 3 次)：終止自動迴圈，升級交由人類工程師介入。
6
Step 6: 機械記帳與歸檔 (Bookkeeping & Audit) ✍️ scribe (Haiku)

將結果客觀謄寫至 docs/agent/ (TASK.md, BUG_FIX.md, PROGRESS.md)。嚴格遵守「先寫入目標歸檔、驗證後再刪除來源 (Insert-before-delete)」 原則。

06. Hook 機制與安全防護系統 (Hook System Deep Dive)

route 插件不依賴提示詞自律，而是透過 Claude Code 的 Hook 系統實現真正的邊界強制隔離與可觀測性：

Hook 事件 觸發時機 / Matcher 執行腳本 核心防護與觀測目標
SessionStart 會話剛啟動時 routing_observe.py 注入 [routing] Brief 提示詞、啟用角色清單與當前未完成 Task/Bug 統計。
PreToolUse Write|Edit|NotebookEdit routing_guard.py 阻擋跨角色越權寫入（如 Builder 寫測試、Scribe 寫代碼、Boss 寫代碼彈出確認）。校驗時間戳防偽。
PreToolUse Read routing_guard.py 阻擋主會話讀取超過閥值 (預設 32KB) 的大檔案，防止 Context 污染；阻擋 Scribe 無邊界全讀 archive。
PreToolUse Agent|Task routing_guard.py 直接拒絕 (deny) 已停用角色；攔截昂貴的內建探索代理 (explore)，建議改用 scout。
PreToolUse Bash routing_guard.py 正則過濾引號，啟發式偵測寫入行為；阻擋唯讀角色與 Scribe 執行 VCS (git commit) 變更。
PostToolUse Read|Grep|Glob routing_observe.py 累計主會話探索次數，超過門檻 (預設 12 次) 發出警示提醒分派 route:scout。
PostToolUse Agent|Task routing_observe.py 當 builder 完成返回時，自動注入 Step 4 審查政策提醒 (review_nudge)。
SubagentStart / Stop Subagent 啟動/停止 routing_observe.py 將分派事實寫入 .claude/routing/dispatch.jsonl 供 /route:audit 審計。
SessionEnd 會話結束時 routing_observe.py 清理當前 Session 在 .claude/routing/state/ 的計數器暫存檔。
🛡️ Fail-Open 容錯設計哲學
所有的 Guard 守衛與 Observability 腳本皆採用 Fail-Open 原則：若遇到惡意/畸形 Payload、解析失敗或 Python 直譯器異常，腳本一律安靜退出 (sys.exit(0))，絕不阻塞或中斷使用者的開發 Session。

07. 7 大風險審查觸發器 (Risk Triggers)

在預設的 review.policy: "risk" 模式下，只要任務命中以下 7 大風險觸發器之一，Boss 必須分派 route:reviewer 進行獨立審查：

觸發器 ID (Trigger ID) 中文定義與審查條件 典型場景與風險說明
no_red_green 缺乏「修改前失敗、修改後通過」的測試覆蓋 沒有任何測試能在修改前捕捉該行為。單純全綠的測試套件不能證明新改動有效。
persistent_state 涉及跨進程生命週期的持久化狀態變更 資料庫 Migration、檔案系統讀寫、Redis 快取格式、訊息佇列 Schema 變更。
authorization 涉及權限控制與身分驗證決策 JWT Token 檢查、Session 驗證、ACL 規則、API 金鑰校驗。
boundary 涉及外部系統依賴之介面邊界 公開 API 規格、Wire Format、CLI 命令列參數、對外 Public 函式簽名。
silent_calculation 計算錯誤不會拋出例外，只會默默產生錯誤數值 財務損益計算、匯率折算、統計報表、稅率加總。
control_flow 變更控制流程、錯誤處理、重試機制、超時或並發 非同步 Promise 鏈、錯誤捕獲分支、Worker 執行緒調度、網路重試邏輯。
builder_blocker Builder 於實作報告中主動提及阻礙 Builder 在 BLOCKERS 區塊回報了規格衝突或預期外的環境問題。
